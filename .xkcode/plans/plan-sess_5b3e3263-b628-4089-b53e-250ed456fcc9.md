## Context
The existing project is ESP32 firmware with a browser-oriented HTTP interface, but it has no endpoint for direct lamp commands. Create a separate Python desktop app that understands Vietnamese voice requests and produces validated commands for future ESP32 integration, without changing or controlling the existing firmware.

## Implementation
- Add a Python application in a dedicated directory (for example, `voice_app/`), with a Tkinter desktop interface for API settings, microphone recording, transcript, generated command, and status/errors.
- Allow the user to configure an ElevenLabs API key and voice ID, plus an OpenAI-compatible API key, custom base URL, and model. Keep keys out of source code and mask them in the interface; document environment-based configuration without writing secrets to disk by default.
- Record microphone input on demand and send audio to ElevenLabs speech-to-text. Send the transcript to the configured OpenAI-compatible chat endpoint with a constrained Vietnamese command interpretation prompt.
- Validate the model’s response against a small local allowlist, initially lamp on/off and an explicit unrecognized/clarification result. Display structured JSON such as `{"device":"light","action":"on"}`; never treat arbitrary model text as an executable command.
- Use ElevenLabs text-to-speech to play a short Vietnamese response describing the interpreted result. Keep network and audio work off the UI thread, with sensible timeouts and clear errors. Provide a typed-text fallback for testing without a microphone.
- Define a clearly separated command-output hook for future ESP32 integration, but do not send commands to the device or add firmware endpoints. Do not claim physical execution.
- Add dependency declarations, an example configuration without secrets, and a README covering setup, API endpoint expectations, microphone/audio requirements, usage, and limitations.

## Verification
- Add automated Python tests with mocked network/audio services for command parsing and validation, custom endpoint handling, error cases, and ensuring unsupported commands are not executed.
- Run the tests and any available static or syntax checks. If credentials, audio hardware, or network access are unavailable, explicitly report that live speech and TTS testing remains unverified.
